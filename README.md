# EmbeddingGemma 2 · GDG Cochin hands-on workshop

A 38-slide deck, a Colab notebook with three labs, and a WebSocket remote with speaker notes.

## Presenting with the remote

```bash
node server.js                 # no dependencies; PORT=8080 and a random REMOTE_KEY by default
REMOTE_KEY=gdg node server.js  # or choose the key yourself
```

It prints three URLs:

- **Display**: open on the projector / external screen and press F for fullscreen.
- **Remote (this laptop)**: opened on `127.0.0.1` rather than `localhost` on purpose, because browsers share zoom per host and this keeps the projector and speaker page sizes independent. Big ←/→ buttons, a jump-to-slide menu, Blank, an elapsed-time timer, the speaker notes and (on wide screens) a live preview of the projector.
- **Remote (phone)**: the same page over Wi-Fi. Under WSL2 the printed LAN address is the WSL VM's, which phones can't reach; use the laptop URL, or enable WSL mirrored networking / a Windows port proxy.

Only connections carrying the key can control the slides. Opening `index.html` directly (file://) still works with the keyboard, just without the remote.

Keyboard on the display: ←/→ / Space / PageUp/PageDown, Home/End, F fullscreen, B blank, Ctrl + scroll or Ctrl + `+`/`-`/`0` to resize the slides only (remembered per screen).

## Before the event

1. **Colab link → QR code.** Upload `workshop.ipynb` (GitHub or Drive), open it in Colab, and paste the URL into `data-url=""` on `#colab-qr` in `index.html`. The QR is drawn in the page (vendored `assets/vendor/qrcode.min.js`, MIT), so it works offline.
2. **Real map data.** `cd demo && python build_map.py` (needs `pip install -U sentence-transformers`). Slide 9 then shows real model positions and cosine scores. Re-check that each step's caption still matches (`STEPS` in `map.js`).
3. **Demos.** Pre-install AI Edge Gallery on the phone and pre-index a clean photo album; pre-load the browser demo in Chrome; set up the laptop CPU demo (see below). Details are in each demo slide's notes.
4. **Dry-run the notebook** once on a fresh Colab T4 runtime.

## Laptop CPU demo

EmbeddingGemma 2 (text-only 270M LiteRT build, 165 MB) served on the CPU by `litert-lm serve`, queried over its OpenAI-compatible `/v1/embeddings` endpoint. Verified with litert-lm 0.18.0 on WSL2 (Ryzen 7 5800H): about 85 ms per query, about 330 MB RAM for the server.

One-time setup, at home (from the repo root):

```bash
python3 -m venv demo/.venv
demo/.venv/bin/pip install litert-lm==0.18.0
mkdir -p demo/models
curl -L -o demo/models/embeddinggemma-2-text-270m.litertlm \
  https://huggingface.co/litert-community/embeddinggemma-2-text-270m-litert-lm/resolve/main/embeddinggemma-2-text-270m.litertlm
demo/.venv/bin/litert-lm import demo/models/embeddinggemma-2-text-270m.litertlm   # model ID: embeddinggemma-2-text-270m.litertlm
```

On stage:

```bash
demo/laptop_demo.sh                                        # starts the server, indexes 30 sentences, then a search> prompt
demo/laptop_demo.sh --query "my container keeps crashing"  # one-shot
```

`laptop_demo.sh` downloads/imports the model if missing, starts the server in the background (log in `demo/serve.log`), waits for it, runs `demo/laptop_demo.py` and stops the server on exit. To show the raw API by hand:

```bash
demo/.venv/bin/litert-lm serve --host 127.0.0.1 --port 9379
curl -X POST http://127.0.0.1:9379/v1/embeddings -H "Content-Type: application/json" \
  -d '{"model": "embeddinggemma-2-text-270m.litertlm,cpu", "input": "task: search query | text: Hello world"}'
```

The `model` field is `<model ID>,<backend>`. Use `cpu`: Google's example uses `gpu`, which under WSL2 falls back to a software WebGPU path (about 9 s per query, 1 GB RAM). The venv, `demo/models/` and `*.litertlm` are gitignored.
